Does the grouped fish and bird picornavirus module work?

PICO_NOLDR_VP0 groups five genera of fish, bird and seal picornaviruses that share one genome organisation: no leader, and a capsid left as VP0 rather than cleaved. None has enough sequence in BV-BRC to model alone. This audit is mostly about what that grouping does and does not buy, because the answer here is sharper than for any other module in the family.

14 rep contigs ship with the module; 14 of them are the best BLASTn hit for at least one exemplar. Routing was measured against the ten Picornaviridae modules only — nucleotide BLASTn cannot reach the routing threshold across virus families, and leaving the other 56 modules' 558 rep contigs out cut the run time four-fold.

Routing is the part that works. Fourteen references reach every genome in all five genera, which is what shared genome organisation delivers: the nucleotide-level similarity is enough to assign a genome to the module.

07What it cannot do

Shared organisation routes a genome. It does not give you a profile.

For seven of the eleven features, only Pasivirus contributed a cluster at all. VP0, VP3, 2A, 2C, 3A, VPg and 3C are each built from Pasivirus sequences and nothing else. VP1 and 2B add Aquamavirus, 3D adds Limnipivirus, and POLY — the longest and most conserved feature — manages four of the five genera.

The cause is arithmetic, not divergence alone. Limnipivirus contributes 3 sequences to most collections, Avisivirus 3, Potamipivirus 3 and Aquamavirus 1. A profile needs at least two sequences from the same genus that are similar enough to cluster, and with one to three sequences apiece that condition usually fails. The documented member floor of five is unreachable; even the leftover pass, which drops the floor to two, cannot build from a single sequence.

This was diagnosed, a fix was attempted, and the fix did not work. The first build used the documented -m 5 throughout, which let only Pasivirus cluster. The module was rebuilt with the leftover pass at its floor of two, which is the sanctioned route to a small profile. The call rates moved by exactly one genome — POLY from 48 to 49. Reporting that is more useful than reporting the rebuild as an improvement, because it locates the limit precisely: the problem is not the floor, it is that four of these genera have one to three sequences per protein in the entire public record.

So what the module is, honestly, is a Pasivirus module that four other genera route to. That is still worth shipping — a genome that routes and gets its polyprotein called is better annotated than one that routes nowhere — but it should not be described as covering five genera. Closing the gap needs more sequence from those genera, not a parameter change.

Routing works for all five genera; profiles work for one. Pasivirus is called completely, and the other four get the polyprotein and little else because they contribute one to three sequences per protein. A rebuild through the leftover pass changed the result by a single genome, which is the evidence that this is a data limit rather than a tuning one.

08What the run found

The run found that the grouping premise only half holds.

Grouping by genome organisation is the project's partitioning rule, and it is right about what it claims: these five genera do share a layout, and the shared layout is enough for fourteen reference contigs to route all of them. What the rule does not promise, and what this module demonstrates, is that routing and calling are different problems. Profiles need sequence similarity within a feature, and organisation-sharing does not supply it.

The practical lesson for the next grouped module is to check, before building, how many sequences each genus contributes to each feature. A genus contributing fewer than two sequences to a feature cannot be covered by it, and knowing that in advance turns a disappointing coverage run into a declared limitation.
