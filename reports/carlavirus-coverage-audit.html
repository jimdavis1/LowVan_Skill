02How it was built

Split out of Quinvirinae on measurement, not organisation.

All six Quinvirinae genera share the replicase / triple-gene-block / coat protein / NABP layout, so the organisation rule alone would have kept Carlavirus with them. Routing is what separated them: lumped, 25 references reach 81.0% overall, and Carlavirus — 102 clusters over 714 genomes — was consuming a budget the five smaller genera needed. Split, every genus improved, Carlavirus itself by eleven points.

Its dump had been bulk-cleaned before this report was written, so the genome list was rebuilt from the class-wide table and re-fetched: 3,184 genomes, 7,999 features, 4,815 unique sequences.

The coverage curve is 49% at 5 references, 76% at 25, 89% at 50. Carlavirus has 102 clusters over 714 genomes at ≥6 kb, so a 25-reference budget cannot reach the tail however it is spent. This is the documented cost of the project's budget rule, not a defect in the module: everything it routes, it annotates well.

Roughly one genome in four of this genus is not reached by the shipped reference set. Raising the budget, not rebuilding the module, is what would fix it.

07What it cannot do

One real limit, and it is the routing.

23.7% of the genus does not route. 102 clusters is more diversity than 25 references can cover, and the coverage curve is still climbing at 50. That is the binding constraint on this module and no amount of profile work changes it.

No mature peptides. The replicase is a polyprotein whose cleavage sites are not documented for this genus in a form that can be located from the sequence.

The evaluation is a sample — 149 genomes at ≥6 kb, seed 29. Routing in §04 is a census over the whole genus.

The homology rescue has now run on this module. Completed 1 October 2026, closing the item deferred on 30 September. rescue_unassigned.py takes every protein no annotation-string rule matched, blastp’s it against this module’s own collections and adopts each into the feature it matches at ≥80% identity over ≥60% of the query, refusing everything below that rather than sweeping it into a grab-bag. It had never run on this module because it crashed on the trailing tab BV-BRC writes into uniq.seq. 425 of 524 unassigned sequences were adopted; the training set went 3139 → 3463 sequences (+10%) and the profile set 316 → 338. The best result of the six: twelve genomes gained, none lost. The 99 sequences left out are mostly replicase polyprotein and polyprotein fragments sitting just below the 80% identity floor, which is the threshold declining a borderline call rather than sweeping it in. Measured against a control — the shipped module scored on the same 286 genomes with the current JSON — the rescue moved genuinely-clean from 81.5% to 85.7% (12 genome(s) improved, 0 regressed). The earlier comparison against measurements/quality.tsv was discarded: that table predates the 30 September copy_num and vocabulary edits, which on some modules dominate the rescue entirely.

08What the run found

Nothing wrong with the module.

Carlavirus is the control case for this report series. Three other modules were measured for the first time in the same pass and two needed copy_num corrections; this one did not, and its duplicate-call audit is clean. When the same checks that found real defects elsewhere find nothing here, that is evidence the checks discriminate rather than simply complain.

No corrections. 316 profiles, six of six features essential on measurement, 86.6% of genomes clean.
